# Notebook Template

Student notebooks should consistently use the following sections.

## 1. Title and position

State what students built previously, the limitation they encountered, and what this notebook adds.

## 2. Learning objectives

Provide three or four observable outcomes.

## 3. Minimal theory

Explain only the concepts required for the next implementation. Put deeper theory in collapsible optional sections or reference documents.

## 4. Architecture reference

Link to the appropriate file in `diagrams/rendered/`.

## 5. Environment check

Validate required imports, configuration, data, and model connectivity. Explain how to switch to mock mode.

## 6. Known-good example

Provide the smallest complete example students can run before modifying code.

## 7. Observe

Ask students to inspect output and answer targeted questions.

## 8. Break

Supply an input that exposes a limitation of the current implementation.

## 9. Improve

Add one new layer or capability and explain why it exists.

## 10. Exercise

Use TODO cells and explicit success criteria. Avoid vague instructions such as "improve the agent."

## 11. Checkpoint

Summarize what was added, what problem it solved, and what limitation remains.

## 12. Optional extension

Place alternative providers, advanced theory, or additional libraries here.

## 13. Clean implementation

Finish with a concise version or link to the day's project notebook/module.
