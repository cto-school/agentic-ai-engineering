# Progressive Concept Sequence

This document controls when terminology is introduced. Notebooks should not use a term substantially before its assigned stage unless they immediately explain it.

## Day 1

Model, prompt, message, response, context window, temperature, structured output, schema, validation, tool, tool request, observation, agent loop, node, edge, state.

## Day 2

Document, chunk, embedding, semantic similarity, vector store, retrieval, grounding, citation, RAG, knowledge tool.

## Day 3

Conversation history, context budget, message trimming, rolling summary, short-term memory, persistent memory, memory retrieval, plan, side effect, guardrail, permission, human-in-the-loop, interrupt, resume.

## Day 4

Deterministic workflow, role, specialist reviewer, handoff, supervisor, shared artifact, shared state, sequential execution, parallel fan-out/fan-in, trace, golden set, evaluation.

## Day 5

Runtime, harness, registry, policy, execution limit, event, checkpoint, protocol, MCP client, MCP server, tool discovery.

## Concepts deliberately delayed

The following concepts should not dominate early lessons:

- Provider abstraction
- Idempotency
- Retry policy design
- Execution budgets
- Trace/span hierarchy
- Typed events
- Checkpoint persistence
- Threat modeling
- Protocol lifecycle

They may be mentioned informally when needed, then taught explicitly on Days 4 or 5.
